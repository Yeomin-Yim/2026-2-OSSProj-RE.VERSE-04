# 결정 기록 (자율 개발 루프)

규칙
1. **수정 전에** 항목을 만들고 `상태: 예측`으로 둔다. 코드를 고친 뒤에 이유를 지어내지 않는다.
2. 검증 후 `결과`를 채우고 상태를 `확인됨` / `어긋남` / `되돌림` 중 하나로 바꾼다. 어긋났으면 무엇이 예측과 달랐는지 쓴다.
3. 대안을 최소 2개 적고, 버린 이유를 쓴다. "포기한 것"을 반드시 쓴다.
4. 근거는 위치로 적는다 (예: `발표 p23`, `wireframe.md 1.3`, `prototype.html .proj-card`, `ProjectsView.tsx:120`).
5. 커밋 메시지에 결정 번호를 넣는다 (예: `[D007] 그래프 빈 상태 추가`).

형식

```
## D000. 제목 (YYYY-MM-DD HH:MM · 반복 #N · 작업 T00)
- 상태: 예측 | 확인됨 | 어긋남 | 되돌림
- 상황: 무엇이 문제이고 왜 지금 다루나
- 근거: 문서/코드 위치
- 선택지: (a) … (b) … (c) …
- 결정: (x)
- 이유: 왜 이것인가. 신뢰도·UX·범위·비용 중 무엇을 우선했나
- 포기한 것: 이 결정으로 잃는 것
- 예측: 바꾸면 무엇이 어떻게 달라질 것인가 (확인 가능한 문장으로)
- 확인 방법: 어떤 명령·화면·테스트로 확인하나
- 결과: (검증 후) 명령 결과 요약, 예측과의 일치 여부
- 커밋: (해시)
```
